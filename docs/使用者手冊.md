# session-branch-control 使用者手冊

讓 Claude Code 的對話「主線不偏題、支線不遺失」：
想追問概念、想換個前提推推看時，開一條支線去問，答案只在對話下方的閱讀區顯示，不會混進主線；
支線問出名堂了，可以併回主線，或升級成一個能用工具的真正子 session；
所有 session 的分枝關係，在每個分頁裡都看得到同一張地圖。

---

## 1. 三分鐘上手

1. **先在主線正常聊一輪**（支線要等主線至少完成一輪才有脈絡可以分）。
2. 看到不懂的概念，輸入：`/q CRDT 是什麼`
   → 對話最下方出現一塊**和對話一樣寬的 📖 支線閱讀區**，回答好了就顯示在裡面（高度不限）。
   它是嵌在對話裡的一列：之後的對話接在它下面，它跟著往上捲，**一直留在你問的位置**，每條支線各有自己的一塊；
   右側 🌳 脈絡樹面板同時多出一個 `? CRDT 是什麼` 節點。
3. 想知道換個前提會怎樣，也用 `/q`：`/q 如果改用 JWT 而不是 session cookie 會怎樣`（它會推演哪些結論仍成立、哪些會翻轉）
4. 想重看以前的支線：點脈絡樹上的節點（新的在上面），畫面會**捲回當初問它的位置**並展開它，脈絡樹面板同時自動收合（要再看樹就 `/t`）。
   只有那塊已經不在對話裡（`--resume`、`/clear` 或對話被壓縮後，cc 會清掉這種列），才改在對話最下方重新顯示。
   最後看過的那個節點會標上青色的 `◂ 剛看過`。
   **想接著某條支線追問**：在閱讀區按 `↳ 接著追問`，輸入框會預填 `/q `，問的問題就接在它底下；點「● 主線」回到主線。
5. 讀完按 `[▴ 收合]`（或 `/r`）：閱讀區在原位折成一行（不會消失，按 `[▸ 展開]` 原地再打開），畫面**捲回你跳過去之前讀到的地方**。
   只想回去、不收合，按 `[↩ 回原處]`。閱讀區很長、底部超出畫面時，右下角會浮出這兩顆按鈕。
   （回到的是「當時畫面上第一則開頭有露出來的訊息」，它會被捲到畫面頂端；cc 只能捲到某則訊息、不能捲到某一行，所以位置會有幾行的誤差。）
6. 問出結論後，在閱讀區裡按：
   - **併回主線**：讓主線 agent 知道這段結論（不會觸發新的一輪）
   - **⇪ 升級：原地 / 新分頁**：把這條支線變成一個真正的子 session，可以用工具繼續深入

沒有任何輕支線、也沒有其他分枝 session 的 session，開啟時不會自動打開脈絡樹（需要時用 `/t`）。

兩個開合是分開的：`/t` 開合**脈絡樹面板**（只看架構），`/r` 開合**閱讀區**（看內容）。
面板收合時，輸入框上方會留一行迷你列：`🌳 #8 <問題>`，顯示閱讀區正在看（或最後看過）的那條支線，`#8` 是它從主線第幾輪分出；後面有 `[展開樹 /t]` 和 `[📖 閱讀 /r]` 兩顆按鈕。

> 閱讀區只是畫面上的顯示：模型讀不到，`--resume`、`/clear` 或對話壓縮之後也不會留著（支線內容本身有保存，再點一次節點就會在對話最下方重新顯示）。
> 按鈕要在全螢幕版面（`CLAUDE_CODE_NO_FLICKER=1`）才點得到。

## 2. 四個名詞

| 名詞 | 是什麼 | 能不能用工具 | 存在哪 |
|---|---|---|---|
| **主線** | 你目前這個 session 的對話本身 | 能 | cc 的 session 紀錄 |
| **輕支線** | 用 `/q` 開的旁支問答。帶著主線完整脈絡回答，但答案只在側欄 | 不能（只憑已有脈絡作答） | mod 自己保存，跟著 session 走 |
| **重支線（子 session）** | 從某個 session 分叉出來的真正 session，有完整工具能力 | 能 | cc 的 session 紀錄 |
| **Session 地圖** | 同一家族所有 session 的父子關係圖 | — | `~/.claude/session-branch-control/<專案>.json` |

> 輕支線看得到主線裡的一切（包含寫過、讀過的檔案內容），跟主線 agent 自己看到的一樣；
> 但它只能從主線「目前最新」的位置分出，而且主線被壓縮過的細節它也看不到。

## 3. 指令一覽

| 指令 | 作用 | 備註 |
|---|---|---|
| `/q <問題>` | 開輕支線：概念說明，或「如果改成…會怎樣」的推演 | 有選中節點時接在它底下 |
| `/t` | 開合整個面板 | 對話進行中也能用 |
| `/r` | 開合最後看的那塊 📖 支線閱讀區（全寬、嵌在當初提問的位置）；收合時捲回原處 | 對話進行中也能用 |
| `/tree` | 打開面板並把焦點移過去 | 面板太窄沒自動開時用 |
| `/map` | 開合面板裡的「重分支 · session 地圖」區塊 | 對話進行中也能用 |
| `/up` | 把選中的輕支線升級成重支線，**原地**切過去 | 支線要有完成的回答 |
| `/up-tab` | 把選中的輕支線升級成重支線，開在**新分頁** | 同上 |
| `/sub [標題]` | 從目前 session 分出子 session，開在**新分頁** | 不給標題就自動命名 |
| `/sub-here [標題]` | 從目前 session 分出子 session，**原地**切過去 | 同上 |

## 4. 面板怎麼看

```
▾ 輕分支 · 這個 session 的追問（3）     ← 點 ▾／▸ 開合（預設展開）
  ● 主線 ← 新的 /q 接在這
  ├ ? 什麼是 idempotent #18 ⇪           ← 由新到舊排列
  └ ? CRDT 是什麼 #12 ⤴ ◂ 剛看過         ← 最後在閱讀區看過的
    └ ? 如果改用 OT 會怎樣 #12

▾ 重分支 · session 地圖（4）           ← 只在這個 session 屬於某個分枝家族時出現
    ● 重構登入流程
  ▶ ├ ⑂ JWT 實驗 #15 目前              ← ▶ 和綠字＝你目前所在的 session
    │ └ ⑂ refresh token
    └ ⑂ OT 研究 #22 ▣

[⇥ 收合] [📖 閱讀]                      ← 固定在側欄左下角
```

版面一律單行、靠左，標題太長只會被截短加 `…`，不會折行或擠壞排版。兩個區塊的開合狀態會被記住。

**重分支的名稱**：session 有你取的名字（`/rename`）就用它；沒有就用 cc 自動產生的標題（`/resume` 清單裡看到的那個）；兩者都沒有，才用它的第一個提問。前兩者不會因為對話被壓縮而改變。名稱約一分鐘更新一次。

**符號說明**

| 符號 | 意思 |
|---|---|
| `?` | 概念追問（`/q`） |
| `⑂` | 地圖上的子 session（舊版 `/wi` 留下的假設推演節點也用這個圖示） |
| `●` | 主線／根 session |
| `#12` | 從上一層的第 12 輪分出 |
| `…` | 回答中 |
| `✗` | 失敗（例如 session 重啟時還沒答完） |
| `⤴` | 已併回主線 |
| `⇣` | 升級成重支線時，從上層 session 帶過來的支線問答（在子 session 的對話裡也看得到） |
| `⇪` | 已升級成重支線 |
| `▣` | 這個 session 目前開在某個 Orca 分頁 |
| `▶ … 目前` | 你現在所在的 session |
| `◂ 剛看過` | 最後在閱讀區看過的輕支線 |

**點輕支線節點** → 直接在閱讀區打開，閱讀區裡有這些按鈕：

| 按鈕 | 作用 |
|---|---|
| 併回主線 | 把這條支線的問答寫進目前 session 的歷史 |
| ⇪ 升級：原地 | 升級成重支線，這個視窗直接切過去 |
| ⇪ 升級：新分頁 | 升級成重支線，開在新分頁 |
| ↳ 接著追問 | 選中這個節點並在輸入框預填 `/q `，接著問 |
| 刪除 | 這個節點和它底下的追問完全消失，像沒問過一樣；已經從它升級出去的重支線 session 不受影響 |

**點地圖上的 session**（目前所在的除外）→ 出現按鈕：

| 按鈕 | 作用 |
|---|---|
| ▣ 在新分頁開啟 | 在新的 Orca 分頁打開它（已開著就切過去） |
| ⇄ 切換成目前 session | 這個視窗直接換成那個 session（它若已開在別的分頁，會改成幫你切到那個分頁） |
| 🗑 刪除 | 跳出確認視窗，**直接按 Enter 就是確定**（Esc 或 `n` 取消）。會永久刪除它的紀錄檔；它的子 session 改掛到上一層。開在某個分頁裡的要先關掉分頁才能刪 |
| （自動） | session 的紀錄檔被其他方式刪掉後，約一分鐘內、或下次開 session 時，地圖會自動拿掉它；剛建立三分鐘內、或還開在分頁裡的不會被拿掉。從它升級的輕分支會恢復成可再升級 |

要從目前 session 分出新的子 session，用 `/sub`（新分頁）或 `/sub-here`（原地）。

**收合**：面板左下角固定的「⇥ 收合」（不隨內容或捲動移位）、游標在面板上時按 `x`、`ctrl+x x`、或 `/t`。收合狀態會被記住，下次開 session 也是收合的。

## 5. 常見用法

### 追問概念，不打斷主線
`/q <概念>` → 看完答案 → 點「● 主線」繼續原本的工作。主線完全不知道你問過。

### 換個前提推推看
`/q 如果改成 <新前提> 會怎樣` → 不滿意可以選中它再 `/q` 往下推，形成一條推演鏈。

### 支線結論要讓主線知道
選中節點 → **併回主線**。從根到這個節點的整條問答，會以 `<side-branch>` 紀錄寫進主線歷史的最後面。主線下一輪就會讀到；不會觸發新的一輪，主線的快取也不會失效。

### 支線要動手做（讀檔、改碼、跑指令）
選中節點 → **⇪ 升級**。新的子 session 會繼承主線脈絡，支線的每一段問答會以一般對話的樣子接在最後（提問標成【支線追問】），開啟就看得到，不必收合。

> 做法是先寫好子 session 的紀錄檔再開啟它；萬一寫不出來（例如 cc 改了紀錄格式），會自動退回舊做法：問答以隱藏紀錄寫進歷史，並在閱讀區顯示。
- 想留在原處看主線 → 選「新分頁」
- 想直接轉過去 → 選「原地」

### 像瀏覽器開分頁一樣分出子 session
`/sub 試試看別的資料庫` → 新分頁開出子 session。之後在任何一個分頁的地圖上，都能點來點去切換。

---

## 6. 資料存在哪、怎麼清

| 資料 | 位置 | 清除方式 |
|---|---|---|
| 輕支線樹 | cc 的 plugin store（依 session 分開存） | 在面板上刪除節點 |
| Session 地圖 | `~/.claude/session-branch-control/<專案路徑>.json` | 地圖上「🗑 刪除」（連 session 一起刪），或 `uninstall.sh --purge` 全刪 |
| 併回或升級寫入的紀錄 | 對應 session 的對話歷史 | 跟著 session 走 |

## 7. 限制與常見問題

- **`/q` 回覆「沒有回答：nothing-to-fork」**：主線還沒完成第一輪，或剛執行過 `/clear`。先聊一輪再試。
- **面板沒自動出現**：終端機寬度要 144 欄以上才會自動打開，窄的話用 `/tree`。
- **開新分頁只會在 Orca 裡發生**：不在 Orca 時，會把啟動指令複製到剪貼簿，貼到任何終端機執行即可。
- **同一個 session 不要在兩個分頁同時開**：「原地切換」偵測到它已開在別的分頁時，會改成直接切到那個分頁。
- **原地切換後原本的視窗就變成另一個 session**：原本的 session 沒有消失，從地圖點回來即可。
- **輕支線的答案比較短、比較快**：它刻意設計成不長考、精簡作答；要深入就升級成重支線。
